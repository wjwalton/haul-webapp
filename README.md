# Globe Haul Shop Tool

A static web app for the service counter: connect to one Specialized Globe Haul (ST / LT) e-bike over
Web Bluetooth, read everything it reports, and flash the official controller firmware as a repair. No
backend, no accounts, no network calls at runtime. Data leaves only through downloads and print.

Status: **milestone 3**. It connects, asks you to confirm the bike, shows live data, identity and
errors, and runs the controller firmware update. Every attempt can be downloaded as a session log.
The display (HMI) update comes later. See `docs/SPEC.md` for the plan and `docs/DECISIONS.md` for later
decisions.

## Use it

Chrome or Edge on Windows is the verified platform for updates. Reading works in any Chrome-based
browser with Web Bluetooth.

- **GitHub Pages (beta)**: https://wjwalton.github.io/haul-webapp/. Every push to `main` is tested,
  built and published by `.github/workflows/pages.yml`. One-time setup: repository Settings → Pages →
  Source: "GitHub Actions". The published site has no firmware in it, so the update screen asks you to
  load the official file from disk. While testing, it's built as "beta": the header and every update
  log show the version and commit.
- **Laptop, offline (Windows or Linux)**: `npm run laptop` builds a `laptop/` folder. Copy it to the
  laptop. On Windows, double-click `Start Shop Tool.cmd` (nothing to install). On Linux, run
  `sh start-shop-tool.sh` (needs Python 3, and Chrome or Chromium with the Web Bluetooth flag on, see
  the folder's README). Either one serves the app on http://localhost:8173 to that computer only. The
  folder includes the firmware if you have it locally (see below), so keep it private.

Firefox has no Web Bluetooth and no setting to turn it on: use Chrome, Edge or Chromium. On Linux,
reading works; the controller update stays disabled until Linux passes the hardware test.

## Develop

Needs Node 24.

```sh
npm install
npm run dev        # http://localhost:5173, includes a simulated bike (no Bluetooth needed)
npm test           # unit tests (Vitest)
npm run build      # the public site in dist/, with a no-network Content-Security-Policy
npm run laptop     # the offline laptop copy in laptop/
```

## Firmware files

The two official images (`M1B0306s0.bin`, `EH02_Eagotech_5.19.zip`) are Specialized's files and are
**not in this repository**. To build them in, for local and laptop builds only, copy them into
`src/assets/firmware/`. That folder's README lists the exact sizes and SHA-256 hashes. Without them
everything builds and runs, and the update screen loads the file from disk. Either way, only those
files are accepted, checked by full SHA-256.

## Tests and real data

The decoders are compared field by field with the Python reference client's output
(`tests/fixtures/py_*.json`, generated by `tools/make_fixtures.py`). The protocol reference notes, real
bike captures and the firmware are kept out of git. The tests that need them skip when they're absent.

## Safety

The app can only send a short whitelist of frames (`src/protocol/frames.ts`, enforced by tests).
Firmware frames can only be built from a verified, allowlisted image. The controller update is offered
when the stock app would offer it (a newer file, a failed update (`controller_e031`), or a controller
that doesn't answer (recovery)), or when the mechanic ticks "Reflash the same version" on a controller
that already runs the file's version. It never flashes an older version. It never erases logs, writes configuration, unlocks a PIN,
touches assist, current, power or speed limits, or flashes battery firmware. See "Hard safety rules"
in `docs/SPEC.md`.
