# Globe Haul Shop Tool (haul-webapp)

Web app for use with Specialized Globe Haul ST and LT. It's a static web app for the service counter:
connect to one bike over Web Bluetooth, read everything it reports, and flash the official controller
firmware as a repair. No backend, no accounts, no network calls at runtime. Data leaves only through
the download buttons.

**Beta.** Not affiliated with or endorsed by Specialized. A firmware update erases the controller before
writing it again: read [Safety](#safety) before using it.

## Status

Milestone 3, in beta:

- Connects to one bike and asks you to confirm it against the bike's screen. Then it shows live data,
  identity (versions, models, serials) and active errors.
- Updates the controller firmware (the official `M1B0306s0.bin` only). It can also reflash the same
  version as a repair, and recover a controller that isn't answering. Every attempt gives a
  downloadable session log.
- Next: the display (HMI) update (deferred until there's a display to test on), the report and log
  downloads, controller updates on Linux, then iPhone / iPad.

The plan is [docs/SPEC.md](docs/SPEC.md); later rulings are in [docs/DECISIONS.md](docs/DECISIONS.md);
the test with a real bike is [docs/HARDWARE_TEST.md](docs/HARDWARE_TEST.md).

## Use it

| Browser | Read the bike | Controller update |
| --- | --- | --- |
| Chrome or Edge on Windows | yes | yes (the verified browsers) |
| Chrome or Chromium on Linux | yes, after turning on one flag (the app shows how) | not yet: until Linux passes the hardware test |
| Other Chromium-based browsers with Web Bluetooth (Android, macOS) | should work, untested | no |
| Firefox, Safari | no: they have no Web Bluetooth | no |

- **Beta site**: https://wjwalton.github.io/haul-webapp/. Every push to `main` is tested, built and
  published by `.github/workflows/pages.yml` (one-time setup: Settings → Pages → Source: "GitHub
  Actions"). The header and every update log show the version and commit. The site has no firmware in
  it, so the update screen asks for the official file from disk.
- **Laptop, offline (Windows or Linux)**: `npm run laptop` builds a `laptop/` folder. Copy it to the
  laptop. On Windows, double-click `Start Shop Tool.cmd` (nothing to install). On Linux, run
  `sh start-shop-tool.sh` (needs Python 3, and Chrome or Chromium; see the folder's README). Either one
  serves the app on http://localhost:8173 to that computer only. The folder includes the firmware if you
  have it locally (see below), so keep it private.

Before connecting: don't pair the bike in Windows Bluetooth settings (remove it if it is), and close any
phone app connected to it.

## Develop

Needs Node 24.

```sh
npm install
npm run dev        # http://localhost:5173, includes a simulated bike (no Bluetooth needed)
npm test           # unit tests (Vitest)
npm run build      # the public site in dist/, with a no-network Content-Security-Policy
npm run laptop     # the offline laptop copy in laptop/
```

## Firmware files

The two official images (`M1B0306s0.bin`, `EH02_Eagotech_5.19.zip`) are Specialized's files and are
**not in this repository**. To build them in, for local and laptop builds only, copy them into
`src/assets/firmware/`. That folder's README lists the exact sizes and SHA-256 hashes. Without them
everything builds and runs, and the update screen loads the file from disk. Either way, only those
files are accepted, checked by full SHA-256.

## Tests and real data

The decoders are compared field by field with the Python reference client's output
(`tests/fixtures/py_*.json`, generated by `tools/make_fixtures.py`). The protocol reference notes, real
bike captures and the firmware are kept out of git, and the tests that need them skip when they're
absent. No real bike names or serial numbers are in the repository: the simulated bike is `EH02_00001`
with made-up serials.

## Safety

The app can only send a short whitelist of frames (`src/protocol/frames.ts`, enforced by tests).
Firmware frames can only be built from a verified, allowlisted image. The controller update is offered
when the stock app would offer it (a newer file, a failed update (`controller_e031`), or a controller
that doesn't answer (recovery)), or when the mechanic ticks "Reflash the same version" on a controller
that already runs the file's version. It never flashes an older version. It never erases logs, writes
configuration, unlocks a PIN, touches assist, current, power or speed limits, or flashes battery
firmware. See "Hard safety rules" in `docs/SPEC.md`.

Once an update starts there is no stop button: about 4.5 s in, the controller erases its program, and
the bike won't drive until an update completes. If it fails or the link drops, the controller waits in
its bootloader and can be flashed again. Keep the laptop plugged in, lid open, next to the bike. On a
Windows laptop the transfer takes about 4 minutes (the phone app: about 30 s), and the bike's display
shows "bypass" the whole time; don't switch the bike off until the app says it has finished.

Logs and `raw.jsonl` files contain the bike's serial numbers. Don't attach them to public issues.
